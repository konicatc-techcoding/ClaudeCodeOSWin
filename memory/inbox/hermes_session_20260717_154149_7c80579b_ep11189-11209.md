## 建議目標

Telegram session 的問題通常不只是數量，而是：

- 長期閒置 session 佔用 `state.db`、transcript 與索引空間
- 舊 session 可能含有不再適用的 context、任務假設或敏感內容
- 直接刪除會失去可追溯性與恢復能力
- 多個 Telegram DM / topic session 容易讓使用者誤回到錯誤脈絡

因此應把流程分為：

```text
Discover → Classify → Notify / Archive → Grace period → Prune → Audit
```
